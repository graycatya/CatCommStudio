# 需求实现与验证状态

状态：登记模板，尚未进行逐条需求编号、实现盘点或设备验收。

本表只维护实现进度与验证证据；需求结论、优先级和目标版本由关联的需求条目维护。空表不表示产品没有需求，也不代表功能已实现或尚未实现。

## 1. 状态索引

填写时复制占位行，为每个已编号需求登记一行并添加相对链接。以下占位行不是实际需求。

## 2. 更新规则

- 实现状态使用“未评估、未开始、进行中、部分实现、已实现”。“已实现”需要覆盖该需求的全部实现范围，并提供可定位的代码或提交依据。
- 验证状态使用“未验证、部分验证、通过、失败、受阻”。“通过”需要覆盖该需求约定范围的验收条件，并关联实际验证记录。
- 不同平台、模式或设备结论不同时，在适用范围中列明差异；部分通过时不能把整个需求标记为通过。
- 基础库已有接口、设计文档完成、应用代码完成、设备实测通过分别记录，不能互相替代。
- 未完成事项写清具体缺口或阻碍；需求范围变化后重新检查实现和验证记录是否仍适用。
