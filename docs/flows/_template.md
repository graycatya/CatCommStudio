# 流程模板

使用方法：复制为具体流程文件，替换编号、占位文字与 Mermaid 节点。图示只是填写骨架，不代表已确认的产品行为。简单操作可直接写在需求中；独立流程必须关联需求依据。

## FLOW-{MODULE}-{NNN}：{流程名称}

| 字段 | 内容 |
| --- | --- |
| 设计状态 | 待确认 |
| 关联需求 | 待填写需求编号与相对链接 |
| 参与者 | 待填写用户、进程、模块或设备 |
| 起始条件 | 待填写状态、权限及输入 |
| 完成条件 | 待填写成功、失败及取消时的终止条件 |

### 正常与异常路径

```mermaid
flowchart TD
    A["待填写：操作入口"] --> B{"待填写：前置条件满足？"}
    B -->|否| C["待填写：提示与修正入口"]
    C --> A
    B -->|是| D["待填写：执行操作"]
    D --> E{"待填写：执行结果"}
    E -->|成功| F["待填写：成功反馈与最终状态"]
    E -->|失败| G["待填写：失败反馈与资源处理"]
    D -->|用户取消| H["待填写：取消反馈与资源处理"]
```

### 状态转换（按需保留）

以下为抽象状态示例，正式文档应使用业务状态名，并补齐每种事件的处理规则。

```mermaid
stateDiagram-v2
    state "待填写：初始状态" as Idle
    state "待填写：处理中" as Running
    state "待填写：完成状态" as Done
    [*] --> Idle
    Idle --> Running: 待填写触发事件
    Running --> Done: 待填写完成事件
    Running --> Idle: 待填写失败或取消事件
    Done --> [*]
```
