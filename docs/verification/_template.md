# 验证记录模板

使用方法：复制为一次实际验证的记录，填写版本、环境、步骤和结果。尚未执行时保留“未执行”，不能预填“通过”。同一需求可关联多个平台、设备和版本的记录。

## VERIFY-{MODULE}-{NNN}：{验证名称}

| 字段 | 内容 |
| --- | --- |
| 关联需求与验收条件 | 待填写需求链接及 AC 编号 |
| 需求依据版本 | 待填写需求文档的提交版本；未提交时注明 |
| 应用与基础库版本 | 待填写提交或构建标识；存在本地改动时注明 |
| 验证日期与执行者 | 待填写 |
| 环境 | 待填写系统版本、架构、构建方式与必要配置 |
| 设备及对端 | 待填写型号、固件、连接方式或模拟方式 |
| 本次范围 | 待填写覆盖的模式、平台、参数与限制 |

### 前置条件与操作

1. 环境准备：待填写可复现的设置和初始状态。
2. 操作步骤或命令：待填写实际执行内容。
3. 结果采集：待填写日志、截图、输出或数据核对方法。

### 实际结果

| 需求及验收条件 | 预期结果 | 实际结果 | 结论 | 证据 |
| --- | --- | --- | --- | --- |
| 待填写 | 待填写 | 未执行 | 未执行 | 无 |

单项结论使用“未执行、通过、失败、受阻”；“受阻”需说明前置条件为何无法满足。证据使用真实的日志、测试输出或文件链接，记录前清除凭据等敏感信息。

### 本次结论与限制

- 验证结论：未执行。
- 已覆盖的验收条件：待填写。
- 未覆盖项及原因：待填写。
- 已知问题与后续处理：待填写。

完成后更新[实现状态表](../implementation-status.md)中的验证状态、适用范围和本记录链接。旧版本的通过结果不能直接用于宣称新版本通过。
