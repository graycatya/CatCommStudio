# 功能设计模板

使用方法：复制为具体设计文件，记录如何实现已关联的需求。本文是模板，不指定 UI 技术栈、IPC 技术或基础库集成方式。已有多进程方向见[架构文档](../multiprocess-architecture.md)。

## DESIGN-{MODULE}-{NNN}：{设计名称}

| 字段 | 内容 |
| --- | --- |
| 设计状态 | 待确认 |
| 关联需求与流程 | 待填写编号与相对链接 |
| 设计依据 | 待填写需求范围、基础库版本及已确认约束 |

### 职责与调用关系

| 模块或进程 | 职责 | 输入与输出 | 调用或通信对象 |
| --- | --- | --- | --- |
| 待填写 | 待填写 | 待填写 | 待填写 |

### 接口与数据

- 接口或消息：待填写请求参数、结果、错误、关联标识与超时规则。
- 数据结构：待填写配置、运行状态和持久化数据的区别。
- 兼容方式：待填写保存格式、版本变更和迁移策略；不适用时说明原因。

### 生命周期与异常

- 资源归属：待填写设备句柄、任务、线程、进程等由谁创建和释放。
- 并发与回调：待填写执行线程、事件顺序和 UI 更新方式。
- 关闭与故障：待填写取消、超时、断连、进程退出和重复请求的处理。

### 实现与验证计划

- 实现步骤及依赖：待填写。
- 需要验证的关键假设：待填写。
- 验收关联：待填写需求中的验收条件及计划采用的验证方式。
- 待确定的取舍：待填写方案、理由与影响。

实际代码位置、完成程度及测试结果分别登记到[实现状态表](../implementation-status.md)和[验证记录](../verification/_template.md)，设计方案本身不作为完成证明。
